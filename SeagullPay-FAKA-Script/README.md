# 鸥卡 (Oka) 极简自动发卡系统使用文档

## 🌟 系统简介
鸥卡 (Oka) 是一款极致轻量的单文件 PHP 发卡系统，专门为配合SeagullPay 支付网关自动化脚本（https://github.com/lyt20/SeagullPay/tree/main/SeagullPay-Merchant-Script）而设计。
本系统主打 **“单文件部署”、“纯异步无刷新交互 (PJAX)”** 以及 **“极致的安全防护”**，非常适合个人开发者、虚拟商品销售者快速搭建属于自己的自动化售卡平台。

### ✨ 核心特性
- **单文件架构**：整个前端页面、后台管理、数据库逻辑均封装在 `jhm.php` 单个文件中，开箱即用。
- **无感刷新 (PJAX)**：全站采用 AJAX + PJAX 引擎，页面切换、表单提交、弹窗提示均无缝衔接，体验媲美大型原生 APP。
- **轻量级数据库**：原生集成 SQLite3，自动生成并管理 `faka.db`，无需额外部署 MySQL。
- **动态库存与超卖保护**：通过强力的 SQLite 事务锁 (Transaction)，彻底杜绝高并发下的“库存超卖”或“重复提卡”问题。
- **全方位安全加固**：
  - **动态风控限流**：内置 SQLite 真实 IP 限流机制，拦截恶意 CC 攻击、后台密码爆破和高频查询。
  - **IDOR 防护闭环**：通过邮箱查询时，自动对“卡密”和“订单号”进行掩码隐藏，防止攻击者通过撞库窃取卡密。
  - **CSRF 跨站防御**：后台所有增删改操作均加入动态令牌防护。
  - **Webhook 防伪造**：回调接口要求校验 `secret` 密钥，防止黑客伪造付款成功请求。

## 🚀 部署与配置

### 1. 环境要求
- PHP 7.4 或以上版本 (需开启 `pdo_sqlite`, `curl`, `mbstring` 扩展)
- 配合 `SeagullPay 支付网关自动化脚本` (运行于本地或服务器的 54321 端口)

### 2. 基础配置
使用文本编辑器（如 VSCode 或 记事本）打开 `jhm.php`，在顶部找到 **【配置区】**：

```php
// ====== 配置区 ======
$admin_password = 'admin'; // 默认管理密码，请务必修改为强密码！
$webhook_secret = 'wh'; // 【安全注意】Webhook密钥，必须与 1.py 保持一致
$db_file = __DIR__ . '/faka.db'; // 数据库存放路径
$api_url = 'http://127.0.0.1:54321/api/create_link'; // 1.py的API服务地址
```

- **第一步**：修改 `$admin_password` 为你的专属后台密码。
- **第二步**：修改 `$webhook_secret`，确保这个长字符串与 `SeagullPay 支付网关自动化脚本` 里面的安全校验密钥一模一样。
- **第三步**：将 `jhm.php` 丢进你的网站根目录，访问你的域名即可！(系统会自动创建数据库文件并锁定权限)

## 💼 后台管理员指南

### 1. 登录后台
在浏览器访问你的发卡网域名，并在网址后面加上 `?action=admin`。
例如：`http://你的域名/jhm.php?action=admin`
输入你配置的 `$admin_password` 即可进入后台控制面板。

### 2. 商品管理
- **发布新商品**：在控制面板输入“商品名称”和“价格(元)”，点击“确认添加”。
- **删除商品**：点击商品列表右侧红色的“删除”按钮。警告：删除商品会**同步清空**该商品下的所有卡密库存，请谨慎操作。

### 3. 库存卡密管理
点击商品列表中的 **“补充卡密”** 蓝色按钮，进入该商品的卡密仓库：
- **批量导入**：在文本框中输入卡密，**一行一条**。支持任意文本格式（如激活码、网盘链接+提取码、长文本说明等）。点击导入后瞬间入库。
- **状态明细**：下方会显示该商品最近的 100 条卡密记录及其状态（“待出售” 或 “已售出”）。

### 4. 订单流水监控
在后台主页的底部，会自动展示最近的 20 笔流水订单，你可以直观地看到：
- 系统订单号、购买的商品、支付金额。
- 客户留存的联系方式。
- 当前支付状态（等待付款 / 付款成功）。

## 🛒 客户使用体验指南

### 1. 购买商品
客户访问首页，选择商品并在下方输入**常用邮箱**（用于未来找回订单），点击“去结算”。
系统会异步请求 `SeagullPay 支付网关自动化脚本` 实时生成付款链接并锁定该笔订单。

### 2. 扫码支付与自动提卡
页面平滑切换至“收银台”后，系统会展示商品详情与支付金额，客户点击“前往收银台支付”完成扫码付款。
- **状态轮询**：停留在本页面的客户，其浏览器每隔 3 秒会向服务器确认一次支付状态。
- **秒级发货**：当客户手机端支付成功，`SeagullPay 支付网关自动化脚本` 会立即向 `jhm.php` 发送 Webhook。页面会自动从“正在等待支付”切换为绿色的“支付成功”，并当场展示完整的激活码。

### 3. 历史订单查询
如果客户不小心关掉了提卡页面，可以点击顶部的“订单查询”。
- **安全查询机制**：
  - 如果输入 **邮箱** 查询：系统会列出该邮箱下的所有订单，但为了防盗，**卡密和订单号都会被强制打码 (显示为 \*\*\*\*\*\*)**。
  - 如果输入 **16位系统订单号** 查询：系统进行精确匹配，并展示完整的提卡卡密。
- **未付款续扫**：如果查询到“未支付”的订单，系统提供快捷入口一键继续支付。

## 🚨 安全与风控 (写给站长)

作为一套暴露在公网的支付系统，鸥卡在底层做了极端的加固，你无需担心以下问题：
1. **同行恶意刷单 / 爆破后台**：系统自带真实 IP 识别与速率限制器（例如：下单接口单 IP 每分钟限 5 次，后台登录限 5 次，全局限 120 次）。超出限制直接熔断。
2. **下载数据库**：系统首次运行时会自动在根目录生成 `.htaccess`，拦截任何试图直接下载 `faka.db` 的 HTTP 请求。
3. **并发超卖漏洞**：就算 100 个人在同一毫秒购买最后 1 个库存，SQLite 的底层排他锁事务也能确保只有第一个人拿到真实的卡密，其他人会提示“库存不足”。
4. **越权偷卡 (IDOR)**：绝不允许“输入别人邮箱就能把别人的激活码看光”的情况发生，严格的脱敏策略让“猜邮箱偷卡”成为不可能。
