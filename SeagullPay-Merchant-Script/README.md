# 众鸥支付 (Seagull Pay) CLI 自动化助手 - 使用文档

本脚本（`1.py`）是一个专为“众鸥支付”定制的高级自动化控制台工具，不仅提供实时的账单监控看板，还内置了**微服务 API**、**Webhook 异步回调**以及**高强度的资金安全防御机制**。

---

## 1. 核心功能概览

- **极速监控**：每隔 2 秒自动轮询一次最新的余额、收款链接状态和交易记录，通过无闪烁 CLI 界面实时展示。
- **本地微服务 API**：内置 HTTP Server，供其他业务系统或脚本静默调用生成带 16 位唯一单号的收款链接。
- **Webhook 异步回调**：监控到合法的订单被支付后，自动向您的业务服务器推送通知。
- **智能退款防御**：自带“金额校验”、“10秒防网络延迟兜底”、“订单核销防重放攻击”等多重防御。任何违规、差额、恶意重复打款均会被全额原路退回。

---

## 2. 配置文件 (`config.json`) 说明

第一次运行脚本时，程序会要求您在终端输入邮箱、密码和 Webhook 网址，输入后会自动在同目录下生成 `config.json` 文件。

文件内容结构如下：

```json
{
    "email": "您的登录邮箱@xxx.com",
    "password": "您的密码",
    "webhook_url": "https://您的回调接收地址",
    "api_port": 54321
}
```

- **`webhook_url`**：当订单被成功付款时推送通知的目标网址（留空则不触发推送）。
- **`api_port`**：本地 API 服务的端口（默认为 `54321`，如被占用可手动修改该值并重启程序）。

> **注意**：除了 `config.json`，程序还会在同目录生成 `processed_tx.json`（已处理交易库）和 `fulfilled_links.json`（已核销订单库），请**绝对不要手动删除**这两个文件，否则可能导致历史订单被重复退款或重复判定。

## 3. 本地 API 服务 (创建收款单)

程序启动后，会在本地监听指定的端口（默认 `127.0.0.1:54321`）。您的发卡网、网站或其他业务后端可以直接通过 HTTP 请求调用它来获取支付链接。

### 接口详情

- **请求方式**：`GET`
- **请求地址**：`http://127.0.0.1:54321/api/create_link`
- **请求参数**：
  - `amount` (必填)：收款金额，例如 `10.5`

**Curl 调用示例**：
```bash
curl -X GET "http://127.0.0.1:54321/api/create_link?amount=10.5"
```

**成功返回示例**：
```json
{
    "status": "success",
    "data": {
        "note": "A1B2C3D4E5F6G7H8",  // 系统自动为您生成的 16位 唯一订单号
        "code": "pay_code_string",   // 前端直接用于展示或跳转的提取码/代码，您的程序前端应在浏览器自动跳转到：https://seagull.teft.cn/pay.php?id="pay_code_string"以支付这笔订单
        "amount": 10.5
    }
}
```
示例：{"status": "success", "data": {"note": "29QJ0JWKPBD6ZIF7", "code": "1573FFFBD282880B", "amount": 1.01}}

**失败返回示例**：
```json
{
    "status": "error",
    "message": "Invalid amount" 
}
```

## 4. Webhook 回调机制 (订单发货通知)

当有一笔转账进入您的账户，且满足**金额正确**、**订单号匹配**、**未被核销过**时，程序判定订单支付成功，并立刻向您的 `webhook_url` 发起 HTTP POST 推送。

### 接收数据格式 (JSON)

程序将把以下数据以 `application/json` 的形式 POST 给您的服务器：

```json
{
    "note": "A1B2C3D4E5F6G7H8",   // 对应 API 创建时的 16 位单号
    "amount": "10.50",            // 实际到账金额
    "sender": "付款人邮箱账号" // 付款人信息
}
```
示例：{"note": "29QJ0JWKPBD6ZIF7", "amount": "1.01", "sender": "2232908600@qq.com"}

### 业务端响应要求 (非常重要)

您的服务器在接收并处理完该回调（例如给用户自动发货、加积分）后，**必须返回纯文本的 `ok`**（忽略大小写）。

**无限重试保障机制**：
- 如果您的服务器返回了 HTTP 500、网络超时，或者返回的内容不是 `ok`。
- 本程序会认为您的业务端**处理失败**，为了防止漏单，程序会将其挂在后台，**每隔 10 秒**无限循环尝试重新推送。
- 直到您的服务器成功处理并返回 `ok` 为止。

## 5. 安全防御与退款判定逻辑

程序内置了高强度的资金防御体系，以下情况均会触发**全额原路退款**：

1. **差额支付**：金额与订单要求的金额不一致（如订单 10 元，转账 0.01 元）。
2. **无头转账**：转账备注为空，或者备注的不是合法的 16 位订单号。
3. **恶意重放攻击（重复付款）**：订单号正确且已被支付成功过。黑客尝试二次转账。程序通过比对本地 `fulfilled_links.json`（核销库），发现该订单号已被使用，会立刻退回第二笔资金。
4. **错位支付/延迟支付**：订单状态是 `pending` (未完成)、`canceled` (已取消)，却依然收到打款。（针对网络延迟，程序特设了 `10秒二次复核` 机制。收到钱后若状态还是未完成，会耐心等待 10 秒后重新强制查询服务器。若 10 秒后依然未完成，才会下发退款）。

> **吞钱情况（免责警告）**：当程序判定需要退款，并向官方 API 提交退款请求时，如果官方 API 连续 3 次超时崩溃彻底连不上，为防止程序死循环，程序将放弃该笔退款，此时资金将留在您的账户，并在屏幕留下红色日志，需要您**手动处理**。

## 6. 交互式界面控制

在 CLI 界面运行期间，您无需停止程序即可进行快捷操作：

- **按下 `C` 键**：暂停刷新控制台，进入手动创建收款链接的交互界面。输入金额后自动生成链接并恢复后台监控。
- **输入 `q`**：在创建链接输入金额时，随时可以输入 `q` 退出创建模式。
- **按下 `Ctrl + C`**：安全中断退出程序（退出前会清屏）。
